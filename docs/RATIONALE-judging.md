# 평가 기준별 근거: 초보 농부 스타트 패키지 (청도 농가 코파일럿)

> 2026-11-05 작성. 발표 자료와 PRD의 "평가 기준 대응" 절에 옮겨 쓰기 위한 참고 자료다. 수치는 모두 출처가 있는 실제 값이고, 출처가 없는 효과 수치는 쓰지 않는다.

## 한눈에

| 항목 (배점) | 우리 주장 한 줄 | 심사 AI가 확인할 증거 |
|---|---|---|
| Copilot SDK · Agent Framework (25%) | 전문 에이전트 여러 개를 4가지 패턴으로 엮고, 다른 모델의 Judge가 근거를 검증한다 | TRD 에이전트 표, 워크플로 코드, 화면의 단계·도구 호출 스트리밍 |
| 생산성 · 문제 적합성 (18%) | 청도 새내기 농부가 6곳에 흩어진 정보를 찾고 손으로 적던 일을 한 번의 기록으로 끝낸다 | 대상 사용자 정의, 청도 실제 통계, 시연 전후 단계 수 |
| Azure 통합 (18%) | `aspire deploy` 한 번으로 Container Apps에 반복 배포, 헬스 체크·추적 포함 | 기본 도메인 URL, `/health`, 배포 명령 문서 |
| 기능 완성도 (16%) | 사진 → 진단 → 기록 → 일정 한 흐름이 로그인 없이 끝까지 동작 | E2E 시연, 오류·대체 처리 |
| UX · 워크플로 (12%) | AI가 하는 일을 단계로 보여 주고, 저장은 항상 사용자가 승인 | 진행 표시, 취소, 승인 버튼, 출처 표시 |
| 책임 있는 AI · 보안 (6%) | 약제명·희석 배수를 만들지 않고, 근로자 개인정보를 받지 않는다 | 결과 스키마, 금지 규칙, 비밀값 관리 |
| 혁신성 (5%) | 진단 앱은 이미 있다. 우리는 진단 결과가 기록·일정·농기계·지원사업으로 이어지는 "한 번 기록, 여러 번 활용" 구조다 | 기존 서비스 비교표, 통합 흐름 시연 |

## 1. Copilot SDK · Agent Framework 활용 (25%)

**주장**: 기능 수가 아니라 깊이로 평가받는다. 에이전트마다 역할과 도구를 나누고, 작업 성격에 맞는 패턴을 골랐다.

| 근거 | 내용 |
|---|---|
| 에이전트 분리 | 안내(Triage), 기록 정리, 날씨, 병해충, 작업 계획, 사진 진단, 대처 안내, 농기계 추천, 지원사업 매칭, 번역, 검증(Judge) |
| 패턴 선택 이유 | 안내 → 전문 에이전트: **Handoff** / 날씨와 병해충은 서로 기다릴 필요가 없어 **Concurrent** / 일지 정리 → 일정 등록은 순서가 있어 **Sequential** / 진단 결과는 작성자와 검토자가 주고받는 **Group Chat** |
| 도구 호출 | 날씨·병해충·도감·지원사업·농기계·기록 저장을 MCP 서버 도구로 분리. 응답마다 `source`, `fetchedAt`, `sourceUrl` |
| 검증 | Judge 에이전트는 **다른 모델**로 사진 특징과 도감 증상이 맞는지 다시 확인하고, 근거 없는 후보를 뺀다 |
| 스트리밍 | AG-UI 이벤트로 단계 시작·도구 호출·부분 응답을 화면에 바로 보여 준다 |

**근거의 출처**: 대회 발표(MS 수석 디벨로퍼)에서 권장한 3층 구조(Agent Framework · MCP · Aspire), 다중 에이전트 패턴, Judge 에이전트, "결과 이유를 보여 주고 다른 모델로 검증" 원칙을 그대로 따랐다.

**시연에서 보일 것**: 사진 진단 한 번에 에이전트 4개가 움직이는 단계 표시, Judge가 후보 하나를 빼는 장면.

**피할 위험**: 에이전트 이름만 많고 실제로는 프롬프트 하나인 구조. 에이전트 수는 실제로 구현한 것만 적는다.

## 2. 생산성 향상 · 문제 적합성 (18%)

**대상 사용자**: 청도의 청년·귀농 1~3년 차 농부. 반시·복숭아 등 과수, 계절근로자와 함께 일하는 농가.

**실제 문제와 근거**

| 문제 | 청도 실제 데이터 | 출처 |
|---|---|---|
| 증상을 봐도 무슨 병인지, 지금 무엇을 해야 할지 모른다 | 농촌진흥청이 매달 병해충발생정보를 낸다(제14호, 2026.11.1~11.30). 새내기는 이 공문과 내 밭 증상을 연결하기 어렵다 | 농촌진흥청 |
| 날씨에 따라 할 일이 바뀐다 | 11/5 비(최저 10℃), 11/7 최저 -1℃로 서리 가능 → 덮개·관수 판단이 필요한 주간 | 기상청 자료 기반 기사 |
| 농기계를 사기 어렵고 빌리는 곳을 모른다 | 청도군 농기계임대사업소 본소·산서·산동 3곳, 62종 785대 운영 | 청도군 기사 |
| 지원사업 조건을 몰라 놓친다 | 청년농업인 영농정착지원사업: 만 18~40세 미만, 독립영농 3년 이하, 월 최대 110만원, 최장 3년 | 아주경제 |
| 외국인 근로자와 작업 지시·서류 관리가 어렵다 | 2026년 청도 127개 농가 450명 계절근로자, 2026~2030 지원체계 10억5,200만원 | 매일신문 |

**생산성 효과를 말하는 방법**: 효과 수치를 만들지 않는다. 대신 **단계 수 비교**를 시연으로 보인다.
- 지금: 사진 찍기 → 검색 → 도감 비교 → 수첩 기록 → 달력에 적기 → 임대사업소 전화번호 찾기 (앱·사이트 4~6곳)
- 우리: 사진 한 장 → 확인 버튼 → 기록·일정·농기계 안내까지 한 화면

**피할 위험**: "작업 시간 70% 절감" 같은 근거 없는 수치. 쓰려면 (예시) 표시를 붙인다.

## 3. Azure 클라우드 통합 (18%)

| 근거 | 내용 |
|---|---|
| 실제 배포 | Azure Container Apps 기본 도메인(`*.azurecontainerapps.io`)으로 제출 |
| 반복 가능 | `az login` → `aspire deploy` 한 줄, 정리는 `aspire destroy`. README에 명령 그대로 기록 |
| 안정성 | 헬스 체크(`/health`), 자동 확장·Scale-to-Zero |
| 관찰 | OpenTelemetry 추적 → Aspire 대시보드 또는 Application Insights |
| 비밀값 | Copilot 인증 정보·공공 API 키는 Container Apps 비밀값에 둔다 |

**피할 위험**: 쓰지 않는 Azure 서비스를 목록에만 넣기(형식적 추가는 감점). SQLite 파일 저장은 컨테이너 재시작 때 사라지므로, 시연 데이터 저장 방식을 TRD에 솔직히 적는다.

## 4. 기능 완성도 · 기술 구현 (16%)

- **로그인 없는 시연 시작** 버튼 하나로 가상 농부 프로필 로드 (막히면 전 항목 최저점이므로 1순위)
- 핵심 흐름 하나를 끝까지: 사진 진단 → 기록 저장 → 일정 등록 → 농기계 안내
- 오류 처리: 공공 API 실패 시 `seed/` 스냅샷 + "기준 시각·출처" 표시, AI 형식 오류 시 1회 재요청 후 저장 안 함, 흐린 사진은 "판단하기 어려워요"
- 반응형: 휴대폰 화면 기준(밭에서 쓰는 앱)

**피할 위험**: 기능 12개를 반만 만드는 것. 공급량 예측(S6)·커뮤니티(S7)는 화면 설명이나 "시뮬레이션" 표시로만 두고 핵심 흐름을 완성한다.

## 5. 사용자 경험 · 워크플로 (12%)

| 심사 관점 | 우리 설계 |
|---|---|
| AI의 자연스러운 통합 | 별도 챗봇 창이 아니라 사진·기록 버튼 안에서 AI가 동작 |
| 지연 처리 | 단계별 진행 표시와 취소 버튼 |
| 투명성 | 결과마다 근거와 출처 링크, "AI 추정" 표시, 확신 정도 |
| 사용자 통제 | 저장·일정 등록은 항상 사용자가 승인 버튼을 눌러야 실행 |
| 접근성 | 큰 글씨, 쉬운 존댓말, 음성 입력, 근로자용 영어·필리핀어 번역 |

## 6. 책임 있는 AI · 보안 (6%)

- **처방하지 않는다**: 약제명·희석 배수를 만들지 않고 "등록 약제는 농약안전정보시스템에서 확인"으로 링크한다. 농약 오남용은 실제 피해로 이어지기 때문이다.
- **환각 완화**: 도구 결과에 없는 수치·자격·날짜를 만들지 않는 인스트럭션, `evidence` 필수 스키마, 다른 모델 Judge.
- **개인정보**: 농부는 나이대·연차·작물·면적만. 근로자는 별칭·사용 언어·근무 기록만, 여권번호·외국인등록번호·연락처는 받지 않는다. 사진의 위치 정보(EXIF)는 지운다.
- **판정하지 않는다**: 근로 기준 위반이나 지원사업 자격을 단정하지 않고 "해당될 수 있음/확인 필요"로만 표시.
- **프롬프트 인젝션**: 공고문·사용자 입력 속 문장은 지시로 따르지 않는다.
- **비밀값**: 저장소에 키를 넣지 않는다.

## 7. 혁신성 (5%) — 독창성 근거

**먼저 인정할 사실**: 사진으로 병해충을 진단하는 앱은 이미 있다.

| 기존 서비스 | 하는 일 | 출처 |
|---|---|---|
| 농촌진흥청 '스마트병해충 진단 서비스' | 31개 작물, 병해충 182종 사진 진단과 방제 약제 추천 (2024.9 공개) | 뉴스서울 |
| 팜모닝 | 농업 정보·커뮤니티 앱 | App Store |
| 제주 스마트 병해충 예찰 진단 앱 | 지역 단위 예찰·진단 | 뉴스서울 |

그래서 "사진 진단"을 독창성으로 내세우면 심사 AI가 "단순 모방"으로 볼 수 있다. 우리 독창성은 아래 네 가지다.

1. **한 번 기록, 여러 번 활용**: 기존 앱은 진단에서 끝난다. 우리는 진단 결과가 영농일지 → 날씨 반영 일정·알림 → 필요한 농기계와 청도 임대사업소 안내 → 지원사업 서류(영농 기록)로 이어진다. 새내기 농부의 "다음에 뭘 하지?"까지 답한다.
2. **진단을 검증하는 다중 에이전트**: 진단 에이전트와 다른 모델의 Judge가 서로 확인하고, 당일 병해충발생정보·날씨와 맞는지 교차 확인한다. 결과마다 출처와 조회 시각을 붙인다.
3. **청도 지역 맞춤**: 청도 임대사업소 3곳, 청도 계절근로자(필리핀) 작업 지시 번역, 청도 지원 프로그램을 한 앱에 묶었다. 전국 앱이 다루지 않는 지역의 빈틈이다.
4. **기록이 쌓이면 지역 신호가 된다 (확장 계획)**: 익명화한 증상 기록과 날씨를 모으면 병해충 확산·출하 시기 신호를 미리 볼 수 있다. 오늘은 시뮬레이션으로만 보이고, 실제 예측이라고 주장하지 않는다.

**발표 문장 예시**: "진단 앱은 이미 있습니다. 하지만 진단 다음에 무엇을 해야 하는지까지 이어 주는 앱은 없었습니다."

## 발표·PRD에 옮길 때 지킬 것

- 출처 없는 효과 수치는 쓰지 않거나 (예시)를 붙인다.
- 실제로 구현한 에이전트·도구만 적는다. 심사 AI는 PRD/TRD와 앱 동작을 함께 본다.
- 기존 서비스 비교표를 넣으면 혁신성 주장이 오히려 더 믿을 만해진다.
